最初は小さな機能をプロジェクトに追加しました。しかし、より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLI は組織の既存のワークフローに沿って動作するため、適切な方法で適切な機能を構築できます。ここから数回の演習では、issue を起点に新機能を作り、コードの妥当性と機能の動作を確認し、最終的にプロジェクトへマージするという、人工知能（AI）エージェントを活用した一般的な開発プロセスを進めます。

> [!NOTE]
> この機能のワークフロー全体を通じて、同じ会話とブランチを使います。通常は、扱うファイルの種類ごとに異なるブランチや pull request（PR）を使いますが、ここでは主な概念に集中できるよう簡略化しています。

この演習では、次のことを行います。

- GitHub issue から新しい Copilot の会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードを確認します。
- 転送されたブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの命令を更新し、既存の `quality-checks` skill をカスタマイズし、MCP による検証を追加して QA agent を作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がゲームをカテゴリや販売元で絞り込めるようにする必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておきたい詳細があります。Plan モードでその判断を整理してから、範囲を限定した実装を Autopilot に任せます。

## 背景

AI コーディング エージェントを開発ワークフローに導入しても、基本は変わりません。むしろ、基本がいっそう重要になります。多くの開発者は、次のような流れで作業します。

1. 実施内容を記載した issue から始めます。
2. 構築するものの計画を立てます。
3. コードを作成して確認します。
4. テストを実行し、コードを検証します。
5. 新しい機能を手動で検証します。
6. pull request（PR）を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、多くの場合は上記の流れを調整したものになります。

この標準的な進め方に従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じ確認プロセスを経るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントが変更を提案し、次に進む前に入力を待つため、開発者とエージェントが一緒に作業します。
- **Plan**: エージェントが先に計画を作成し、プロジェクト ファイルを編集できない状態になります。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクが完了したと判断するまで自律的に作業を繰り返します。

最初に Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から始める

フィルタリング機能の作業に取りかかる前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルをまだ開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd>（Mac）または <kbd>Ctrl</kbd>+<kbd>\`</kbd>（Windows/Linux）を押します。
4. `main` を更新してから、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7`（または同様の番号）が追加されていることを確認してください。`#` を使うと、GitHub 上の issue や pull request（PR）をコンテキストに含められます。

## フィルタリング機能を計画する

計画を立てることで、機能の実装やタスクの実行を Copilot に任せる前に、進め方を定義できます。複雑な作業では、少し時間をかけて計画することをお勧めします。Plan モードに切り替え、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査して、最適な進め方を判断し、計画を作成します。

3. 作業中、フィルタリング機能の動作について質問されることがあります。希望に基づいて回答してください。正解はひとつではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd>（Mac）または <kbd>Ctrl</kbd>+<kbd>E</kbd>（Windows/Linux）を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 自分の判断と一致しない部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画が作成され、内容を確認できたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Copilot は、完了したと判断するまで問題に取り組み、作業を繰り返します。

1. **Accept plan and build on autopilot (recommended)**、またはインストールしたバージョンで同様のラベルが付いた選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が合意済みの計画に沿って作業を繰り返し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まることがあります。先に計画を確認してください。Copilot から依存関係の不足やポートの競合が報告された場合は、チェック完了とみなす前にセットアップの問題を解決してください。

## 実装を確認して検証する

コードが生成されたら、ほかのコードと同様にマージ前に確認します。コードを確認し、サイトを実行してすべてが正しく表示されることを確かめます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** も **Autopilot** も表示されていないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを確認します。
3. 結果を issue および計画中に決めた内容と照らし合わせます。
4. コードの確認が終わったら、<kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新しい機能を試す

コードに問題がなさそうでも、実際に動くか確認しましょう。前と同じようにアプリを起動し、Codespaces で転送されたポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリによるフィルタリング、販売元によるフィルタリング、および計画で合意した組み合わせを試します。
4. リセット時と検索結果がない場合の動作が、issue と合意内容に一致することを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

異なる会話モードを使って、機能を構築し、確認しました。この演習では、次のことを行いました。

- GitHub issue から新しい Copilot の会話を始めました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードを確認しました。
- 転送されたブラウザーで機能を手動で検証しました。
