GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行するなど、自律的に作業します。作業は開発者のマシンでリアルタイムに実行されるため、VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集を進行中に確認できます。差分をインラインで確認し、変更ごとに採用または却下できます。また、エディターを離れずに追加のプロンプトを送って会話を導き、作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集を確認して採用します。
- 作業中のセッションに指示を追加し、ハイ コントラストに加えてライト モードの切り替えを依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタム エージェントが、ハイ コントラスト モードを実装しています。作業中に、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのため、ライト モードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集内容を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの呼び出しを確認します。ファイルの読み取り、ファイルの編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消して、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行など、ツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、行った変更をまとめたメッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードの実装が完了したので、同じ会話を続け、ライト モードの切り替えを追加します。同じチャット セッションを使うと、エージェントは前の作業で扱ったコンポーネント、スタイルの方法、設定を local storage に保存するパターンなど、すべてのコンテキストを保持します。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を続け、すでに行った変更を調べてからライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を使います。
4. 望まない方向にエージェントが進んだ場合（たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとした場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、説明を補うフォローアップ メッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を追加する方が、最初からやり直すよりも速く進められます。フォローアップ プロンプトを使い、調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」）、方向修正（「3 つ目の切り替えボタンを追加せず、既存の設定パネルにライト モードを組み込む」）、範囲の拡張（「両方の切り替えにキーボード ショートカットも追加する」）を依頼できます。

## 作業内容を確認する

変更をコミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン（Accessible Rich Internet Applications（ARIA）属性、キーボード ナビゲーション、セマンティック HTML、local storage を使った設定の保持など）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の演習で公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して指示しました。ファイルの編集を確認しながら採用または却下し、コンテキストを保ったままフォローアップ プロンプトを送って作業を拡張しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイルごとの編集を採用または却下しました。
- フォローアップ プロンプトを使い、作業中のセッションに指示を追加しました。

[次の演習][next-lesson]では、アクセシビリティに関する作業を pull request として公開し、このラボを通じてローカルのカスタム エージェントが生成した変更を確認します。
